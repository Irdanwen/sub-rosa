# Office add-ins (Word, Excel, PowerPoint)

Sub Rosa in a task pane beside a document (parity WP22,
[ADR-0102](adr/0102-an-office-task-pane-is-a-browser-device-whose-session-a-sign-in-window-carries.md)).

| Host | What it does | Office API |
| --- | --- | --- |
| Word | Rewrite, shorten, correct, summarize or translate the selection, or apply a described change; draft text at the cursor (with the web search) | WordApi 1.1 |
| Excel | Explain the selected cell's formula; write a formula for the selected cell from a description; analyse the selected range with Python (Pyodide, when the browser allows it) and write the results to a new sheet | ExcelApi 1.4 |
| PowerPoint | Draft slides from a request, optionally from a pasted note, and add them after the selected slide in the presentation's theme | PowerPointApi 1.2 (1.5 to place them) |

Every answer is a proposal: the document changes only when you press
Replace, Insert, Put it in, Write to a new sheet or Add slides.

## How it signs in

Each pane is a browser device of your account, like a browser using
`/app` (ADR-0096): it has its own Carpe Diem key, limited per day, kept
encrypted in the pane. The first time, press **Sign in**: a window opens on
the Sub Rosa account site, you sign in there, then approve the add-in from the
Sub Rosa app (Settings, Account, Connect another device) with the code the
pane shows. The window closes by itself once the pane has its key. The key is
renewed while you use the add-in; in Office on the web, the pane asks you to
open the sign-in window again when it is about to run out. A pane reads none of
your notes, memories or chats.

In Office on the web the recovery key cannot admit a pane (the code would cross
Microsoft's page); approve it from the app. In the desktop apps, a pane that is
signed in in place offers the recovery key too.

## Files

- `office-addins/manifests/word.xml`, `excel.xml`, `powerpoint.xml`: one
  manifest per host, generated by `node office-addins/scripts/manifests.mjs`
  (`--check` fails when they are stale; `--origin https://… --out <dir>` writes
  copies for another origin, such as a staging account site).
- The pages are served by the account origin at `/office/word.html`,
  `/office/excel.html`, `/office/powerpoint.html`, `/office/session.html` (the
  sign-in window) and `/office/commands.html` (the ribbon button's function
  file). `pnpm build:website` builds them after the site.

## Sideloading

Download the manifest for the host you want from the repository (or build one
for your origin with `--origin`).

### Office on the web

1. Open a document in Word, Excel or PowerPoint on the web.
2. Home, **Add-ins**, **More add-ins** (or Insert, Add-ins), then **My
   add-ins**, **Upload my add-in**.
3. Choose the manifest file and press **Upload**. The Sub Rosa button appears
   on the Home tab.
4. Allow pop-ups for the Office site: the sign-in window is a pop-up.

### Windows (Microsoft 365, WebView2)

1. Create a folder, for example `C:\SubRosaAddins`, put the manifests in it,
   and share it (Properties, Sharing, Share) so it has a network path like
   `\\YOUR-PC\SubRosaAddins`.
2. In Word, Excel or PowerPoint: File, Options, Trust Center, Trust Center
   Settings, **Trusted Add-in Catalogs**. Add the network path, tick **Show in
   Menu**, press OK and restart the app.
3. Home, Add-ins (or Insert, My Add-ins), **Shared Folder**, choose Sub Rosa.

Office 2016 builds that still use Internet Explorer or the first Edge web view
cannot run the panes; Microsoft 365 with WebView2 can.

### Mac

1. Quit the app, then copy the manifest into its `wef` folder (create it if
   needed):
   - Word: `~/Library/Containers/com.microsoft.Word/Data/Documents/wef`
   - Excel: `~/Library/Containers/com.microsoft.Excel/Data/Documents/wef`
   - PowerPoint: `~/Library/Containers/com.microsoft.Powerpoint/Data/Documents/wef`
2. Open the app and a document, then Home, Add-ins (or Insert, My Add-ins) and
   choose Sub Rosa under the developer add-ins.

### iPad

Sideloading on iPad needs a manifest published through the Microsoft 365
admin center; the panes have not been checked there.

## Deployment checklist

1. The account service with `/office/session.html` among its sign-in return
   paths (`subrosa-cloud/crates/services/src/lib.rs`).
2. The `/office/` block of `subrosa-cloud/deploy/nginx-account.conf.example`
   (or the Caddy example, or `website/public/_headers`): its own
   Content-Security-Policy, and no `X-Frame-Options`. The Excel pane's Python
   runs in the site's `/python-sandbox.html` frame (ADR-0104 addendum of
   2026-10-10), so that page's block, whose `frame-ancestors` names Office's
   hosts, and the CORS headers on `/assets/python-sandbox*` and `/pyodide/`
   are needed too.
3. `pnpm build:website` and the usual release switch of the account site.
4. ADR-0096's deployment gates still apply: Carpe Diem must hold the browser
   bound before any pane can obtain a key
   ([browser-device-deployment.md](browser-device-deployment.md)).

## What was checked, and what was not

Nothing has run inside real Office yet. Checked when written (2026-10-08):

- unit tests with Office.js replaced (`src/test/office-addins-*.test.ts*`):
  selection reads, proposals applied only after confirmation, a moved
  selection refused, the analysis range mounted for Python, formulas and
  sheets written where the proposal said, slides inserted after the selected
  one, the sign-in window's relay and its refusals, the manifests' schema
  order, resources and URLs;
- `npx office-addin-manifest validate` on the three manifests: valid (it
  calls Microsoft's online validation service, so it is not an offline check);
- `node office-addins/scripts/smoke.mjs` with Playwright's headless Chromium
  over the built site and the `/office/` policy: each page renders with a
  stubbed Office.js, and with Microsoft's real Office.js outside Office with no
  violation but the telemetry frame the policy refuses on purpose.

To check by hand on each of Windows, Mac and the web before announcing:
the pane loads (frame-ancestors on the web), the sign-in window opens and
closes itself, a pairing approved from the app gives the pane a key, each
action proposes then applies, Python runs in the Excel pane, and Office still
works with its telemetry frame refused.

## External gate: AppSource

Publishing in Microsoft's store (AppSource) is outside this repository: a
Partner Center publisher account, the store's validation of each manifest
(including its policies on privacy statement, support URL, and test
credentials for the reviewers), and Microsoft's review. Until then the add-ins
are installed by sideloading, or by an organisation's administrator through
the Microsoft 365 admin center.

## Languages

The panes use the site's copy (`t()` of `website/src/lib/i18n.ts`) in English
and French, following Office's display language. German, Italian, Spanish and
Brazilian Portuguese follow when the site's catalog gains them. The manifests
carry English and French names and descriptions.
