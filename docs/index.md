- [adr/0089](adr/0089-deep-research-is-one-rust-engine-of-durable-steps-and-study-mode-rides-the-prompt-seams.md) — deep research is one Rust engine for both shells (clarify, an edited plan with its depth and cost ceiling, a run, a report), one row per search and per source (migration 057) re-driven by the sweep, the model numbers and the app resolves citations and writes the sources list, the report is a note exported as Markdown, PDF or a hand-written `.docx` (addendum: the ceiling prices searches and page reads at the operator's per-call prices, and the report note's id is reserved on the row so a resumed run writes one note); study mode is a per-chat row (migration 058) read at the phone prompt and sent after the desktop context marker, with `subrosa:quiz` and `subrosa:flashcards` blocks and an SM-2 review of local `study_cards`
- [adr/0090](adr/0090-office-files-are-written-by-the-app-and-code-mode-reviews-from-a-recorded-start.md) — one `make_document` tool on both shells (agent-lite in-process, the desktop's `june_media` MCP through `/v1/media/document`) backed by hand-written Word, Excel and PowerPoint writers, files kept in the gallery's `documents` folder and shown as a `subrosa:file` card named by file, never path; desktop Code mode records the folder's start (git commit plus copies of already-changed files, or a copy of the folder) and reviews each changed file with a unified diff, kept or reverted only inside the folder (addendum: documents ride the gallery's sync lane and show in the Library's Files, `make_document` is an assistant permission, Code mode can be chosen when starting a chat)
- [adr/0091](adr/0091-assignments-run-where-an-app-is-open-on-the-apps-own-clock.md) — assignments and scheduled tasks are synchronised rows addressed to one device, run on the app's own clock (the latest unrun slot, once, late if need be) only while an app is open, the menu bar included; a desktop run is a one-shot Hermes cron job, a phone run an agent-lite chat with its tools in a task-local; a row another device wrote runs under the errand guards and "run now" is an errand; reviews and feedback travel with the run and feed the next one, and an approved "ask first" proposal is carried out once (migration 060); addendum to the moments: the opt-in daily brief, silent when there is nothing to say and under the same daily cap; addendum 2026-10-08: run jobs carry a machine tag that keeps them out of Routines, and notifications follow the app's language
- [adr/0092](adr/0092-connectors-are-definitions-that-travel-and-access-that-stays.md) — connectors (remote MCP servers, built-in Google and Microsoft) are synchronised definitions with device-local keychain tokens; the phones speak Streamable HTTP MCP with OAuth 2.1 (RFC 9728/8414/7591, PKCE S256, resource indicators) through `subrosa://connector/callback`; one verified catalog for both shells (Hermes on the computer); per-tool allow, ask or deny with every ask a durable `connector_calls` row; interactive views in a sandboxed frame on their own scheme and CSP behind a checked bridge; connector triggers for assignments while the app is open; skill packs for agent-lite and `/name` on the phone; connector sources in deep research; Gmail gated on CASA (migrations 063, 064); addendum 2026-10-08: Hermes reaches the same connectors through the app (`subrosa_connectors` MCP server, rules in the guard ledger, "ask" as Hermes's approval), custom assistants get a "Connectors" permission, GitHub built in through the device flow, real-server tests
- [adr/0093](adr/0093-a-voice-conversation-is-a-cascade-run-in-rust-around-the-shells-own-chat.md) — the voice conversation is a cascade (local energy detector, the dictation's transcription rail, an ordinary chat turn, the reply read back sentence by sentence with one sentence rendered ahead) run by one Rust session on every shell as a pure state machine; the webview sends the turns through the shell's own chat, so history, tools, connectors and memory apply; barge-in silences the speaker then stops the turn; echo is cancelled by Voice-Processing I/O on iOS and the communication input on Android, allowed for by a higher threshold on desktop; protected mode's Voice off is enforced in Rust; a camera frame (phones) or a screen frame (Mac, through the system audio helper) rides the turn to a vision model
- [adr/0094](adr/0094-the-desktop-agent-reaches-past-the-app-only-where-the-person-points.md) — the desktop agent reaches outside the app only where the person points: the agent browser drives an installed Chromium-family browser in a dedicated profile over loopback DevTools (a small WebSocket client, `june_browser` relay MCP, `/v1/browser/request`), consent per registrable domain with an allow list in Settings, Stop, a journal, refusal of password, payment and one-time-code fields and of CAPTCHAs, one egress ledger row per page; the chat bar is a non-activating panel opened by a shortcut the dictation helper registers (Windows: `RegisterHotKey`); "What I'm looking at" (app, window title, selection, optional one-window picture) is opt-in and read only on a click, attached as files
- [adr/0095](adr/0095-the-phones-system-surfaces-are-addresses-and-inboxes.md) — the phones' system surfaces hand over and let the app act: iOS widgets (small Ask, medium Ask/Dictate/Record, Lock Screen Ask) and the Android widget are `subrosa://` links (`chat/new` is a fresh chat), Android `SEND`/`SEND_MULTIPLE` fills the ADR-0048 share inbox in the app's data directory, a shared picture or document goes to a fresh chat's composer, and the share inbox is swept; the Apple Watch app sends a dictated question over WatchConnectivity, the iPhone runs it as an agent-lite chat with a `watch-requests/` promise file re-driven by the sweep, and the watch shows and reads the plain-text answer; three new bundles and profiles in the iOS lane
- [adr/0096](adr/0096-a-browser-is-a-device.md) — a browser becomes a device of its account after a recent sign-in and an out-of-band admission (a pairing a live app approved, or a value derived from the recovery key checked against a verifier the vault holds), with a non-extractable WebCrypto device key that signs a proof on every device call; it obtains its Carpe Diem key through the ADR-0069 path with a `browser` bound Carpe Diem holds (daily cap, one week, no router or x402), keeps it sealed in IndexedDB and renews it while live; the site CSP adds only the operator origin, Trusted Types and SRI; supersedes the "browsers have no device" clause of 0069 and the "read only, not a limitation to lift" consequence of 0053; addendum 2026-10-10: every device proof binds the exact request body (`ath`)
- [adr/0097](adr/0097-a-publication-is-plaintext-the-service-renders-on-an-origin-of-its-own.md) — a note, a canvas, a profile or an assistant made public on purpose: plaintext sent by an explicit publish, rendered once by the account service from markdown through an allowlist (raw HTML as text, no images, web and mail links only) and served as script-free HTML from a publication origin apart from the account origin; a site is an ordered set of pages with a home page; the profile is opt-in; the assistant catalog is public JSON read by the website, and "Add to Sub Rosa" is `subrosa://assistant/import?id=` read back from the app's own account site and added only on a tap; a documented rule set, a report form and an operator takedown tool instead of a model; ADR-0053 shares untouched
- [adr/0098](adr/0098-a-shared-project-is-a-space-whose-key-changes-with-its-members.md) — shared projects and group chats: a space's content is encrypted under a key that changes at every membership change (an epoch), sealed with HPKE to each member's account identity key (X25519 and Ed25519, private halves in the vault), under a hash chain of signed heads with a key commitment that members verify and keep (rollback detected); objects are encrypted and signed by their author; invitations by link carry a one-time secret and the inviter's identity, acceptance is an HMAC only the link can make, safety numbers are compared out of band; a member's own device and key answer for the assistant and the reply says who paid; a preview behind a switch until an independent review of [security/spaces-protocol.md](security/spaces-protocol.md)
- [adr/0099](adr/0099-health-and-finances-are-local-reads-the-person-chooses-to-share.md) — health and finances are local data only: the phone reads the measures the person picks from HealthKit or Health Connect, read only, into one `health_days` row per measure and day (migration 068); bank statements (CSV with a checked column mapping and presets for UBS, PostFinance, Raiffeisen, BCV, Crédit Agricole, BNP Paribas; OFX/QFX; camt.053) become `transactions` (migration 069), deduplicated by bank reference or an occurrence-numbered digest, never notes; rules plus model suggestions the person confirms (descriptions only); sync per health measure and for finances as a whole through the outbox `stays_local` gate; read-only `health_summary`, `spending_summary`, `transactions_search` for agent-lite and, over the local proxy, the desktop's own `june_personal` MCP server; scheduled runs read them only through their "Health and finances" group (addendum 2026-10-08); the budget engine bridge is files only
- [adr/0100](adr/0100-the-browser-extension-reaches-the-app-through-native-messaging-and-a-pairing.md) — the browser extension talks only to the desktop app through native messaging: the signed app binary is the host in a relay mode (detected from the browser's arguments before Tauri starts) that forwards bytes to a Unix socket or per-user named pipe, registered per user and per browser from Settings, never at install; a six-digit code shown for five minutes pairs one extension, whose token is kept hashed and bound to the origin the relay reports; a question is an agent-lite turn filed in the chat list and streamed back from its events, the page read on a click through `activeTab` and sent as a text attachment; "Add to a note" and "Save link to library" reuse `agent_notes` and `saved_items`; the extension is a dependency-free workspace package with its own `_locales`
- [adr/0101](adr/0101-the-web-client-runs-agent-lite-from-rusts-own-words.md) — the web client (`/app`) reads agent-lite's system prompt, tool declarations, memory and personalization words and the travelling tables' columns from `packages/chat-core/agent-lite.json`, which a Rust test renders and keeps in step; framework-free chat logic (context gauge, reasoning effort, speakable text, chat-block fence, conversation Markdown) lives in `@subrosa/chat-core` with each surface's words injected; the browser writes through a TypeScript port of `account/sync.rs` checked by a fixture the app must verify and apply, and keeps only ciphertext in IndexedDB
- [adr/0102](adr/0102-an-office-task-pane-is-a-browser-device-whose-session-a-sign-in-window-carries.md) — an Office task pane is a browser device of its own (ADR-0096) that reads nothing of the account; where its frame has no session (Office on the web) a sign-in window on the account origin relays exactly seven device calls over Office's dialog channel, signing nothing and refusing recovery-key admission; every pane action is proposed and applied on confirmation; the words are Rust's (`web/office.json`, the note editor's rewrites), the loop the web client's; `/office/` gets its own policy (Office.js from Microsoft's CDN under its `officejs` Trusted Types policy, Office's hosts as frame ancestors, telemetry frame refused)
- [adr/0104](adr/0104-the-web-clients-features-run-in-the-tab-under-a-policy-of-their-own.md) — the web client's features (research, study, documents, Python, assignments, connectors, skills, voice, finances, protected mode) plug in as `WebFeature`s through a `FeatureHost`, read Rust's words from `packages/chat-core/web/*.json`, keep durable state sealed in IndexedDB and run only while a tab is open; `/app` alone gets WebAssembly, a blob worker, the view frame, the microphone and camera, and the probed connector origins by name, never `https:`; its 2026-10-10 addendum moves Python into an opaque-origin `/python-sandbox.html` frame with its own policy (and drops `blob:` from `/app`'s `worker-src`)
- [adr/0107](adr/0107-a-connector-a-tab-cannot-reach-is-an-errand-to-an-open-app.md) — a connector a tab cannot reach (an origin it refuses, a custom server, the app's own sign-ins) is offered by an app whose owner switched on "Run connectors for my browser" (`connector_relays`, each tool with that device's rule) and called through a `connector_errands` errand the device answers in the same row under its own rules, single use and perishable within minutes; the tab waits a minute and says which device must be open; each app files its daily brief card with its agenda line (`daily_brief_cards`) and the tab reads a relayed Google or Microsoft calendar; the web client also invites, admits and removes members of a shared project
